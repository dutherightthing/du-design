# Distilled patterns

Our own **encoded judgment** about recurring web components — navbars, CTAs, and so on — distilled from the inspiration galleries in [`../../sources/ROUTER.md`](../../sources/ROUTER.md) so an agent gets the useful conclusion without a live scrape.

## Why these exist (the trade-off)

A pattern note is the *distilled* alternative to scraping a gallery live. Each has a place:

- **Read the note when** you need the judgment fast: which variant fits this brief, what makes it good vs. generic, what to avoid. Zero cost, zero network, always in context.
- **Scrape live when** you need to *see* current examples, extract real tokens (`design-dna`), or the note's exemplar sites have gone stale. The note tells you *what to look for*; the scrape shows you *what it looks like now*.

So the note doesn't replace the gallery — it front-loads the thinking so a scrape (if you still need one) is cheaper and more targeted.

## What belongs here

- **Distilled judgment in our own words:** taxonomy, when-to-use, anti-patterns, a short list of exemplar sites to go look at.
- **NOT** copied gallery content, scraped markdown, or screenshots. Those stay upstream (copyright + bloat). See the no-mirror rule in [`../../sources/ROUTER.md`](../../sources/ROUTER.md).

## Staleness

Exemplar site lists rot — sites redesign. Treat the named sites as *starting points to verify*, not gospel. If several are stale, re-scrape the source (its subpath/category is noted in each file) and refresh the note. Each note carries the date it was last distilled.
