# Slide deck principles

Jerry's #1 gripe with default agents is decks that overload every slide. These rules exist to stop that.

## The cardinal rule: say it once
**Do not repeat the same idea three times on one slide** (headline + body text + a graphic that all restate the same thing). Pick the single strongest way to make the point and cut the rest. A slide is a *support* for the speaker, not a document.

- Headline states the takeaway. Everything else must *add* to it, not echo it.
- If a chart already shows the trend, don't also write "sales went up" — label the chart's insight and stop.
- If an icon is decorative and adds no meaning, remove it.

## One slide, one idea
- If a slide has two ideas, it's two slides. Splitting is almost always better than cramming.
- The audience reads or listens — not both at once. Minimize on-slide text so they listen to *you*.

## Text discipline
- Headline = the takeaway, written as a full claim ("Churn dropped 40% after onboarding v2"), not a topic ("Churn").
- Body: a few words or a short phrase per point. No paragraphs. No full sentences you'll read aloud verbatim.
- Rough ceiling: ~6 words per bullet, ~4 bullets per slide. Fewer is better. If you need more, it's a doc, not a slide.

## Visual hierarchy per slide
- One dominant element (a number, a chart, a headline, an image). Everything else is secondary.
- Consistent template: same title position, same margins, same type scale across every slide. Inconsistency looks amateur.

## Data slides
- One chart per slide, one insight per chart. Title the chart with the insight, not the metric.
- Strip chart junk: no 3D, no needless gridlines/legends, no decorative axes. (See the `dataviz` skill for color/among charts.)
- Highlight the one series or bar that matters; mute the rest.

## Structure
- Open with the point, not an agenda. Agendas are usually skippable.
- Build a narrative: setup → tension → resolution. Each slide advances it.
- Section dividers reset attention — use them sparingly and cleanly.

- HTML decks + PPTX export: see the **decks** skill (huashu-design) in [`../skills/README.md`](../skills/README.md).
- Charts: use the `dataviz` skill for palette and chart-type choices.

## Anti-slop for decks
- Every slide packed edge-to-edge with text and clip art.
- The same message in title, bullets, and image.
- Five fonts, five colors, a different layout every slide.
- Reading full sentences off the screen to the audience.
